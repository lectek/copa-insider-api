- Movido de `README_DEV.md` após registrar as etapas de criação/atualização/validação/pública de produtos no `README.md`.
- Descrevemos os endpoints (`POST /api/admin/produtos`, upload de imagem, validação (`/validar`), publicação (`/publicar`), atualização, exclusão) e os gatilhos de automação (`ProductBackInStockAutomationService`, `EmailCampaignQueue`).
- Documentado o bloco “Clientes (Admin)" com os endpoints críticos (resumo `/api/admin/clientes/{id}/resumo`, detalhe/update parcial, ativar/desativar, pedidos, endereços) e as próximas entregas de reset/OTP e encerramento de sessões; esse registro orienta as próximas implementações.
- Assegurado o ambiente de testes com Docker ou MySQL (comandos `docker-compose -f docker-compose.dev.yml up -d mysql` e `./mvnw test -Dspring.profiles.active=test`) para poder rodar Testcontainers e ITs; essa etapa foi movida do README_DEV para cá para indicar que o setup está pronto e documentado.
- Registrado o `ProdutoAdminRestControllerTest` com cobertura dos endpoints `/api/admin/produtos` (listagem, obtenção, criação com validações, atualização, remoção, upload de imagem, validação/publicação) para provar que o controlador está testado; esse passo sai do README_DEV e fica documentado aqui até o próximo ajuste.
- Removido o passo “Adicionar testes de controlador para `/api/admin/produtos`” do README_DEV depois de criar a suíte `ProdutoAdminRestControllerTest`; registro mantido aqui para lembrar quais endpoints foram verificados e para orientar quando expandir a cobertura.
- Atualizada a API/Swagger: `README.md` já menciona que o `OpenAPI` expõe `/api/admin/produtos` com os parâmetros extras (validador, upload, imagem IA, validar/publicar); esse registro no README_CONFIG confirma que o passo “Atualizar Swagger/OpenAPI com rotas admin de produtos” foi concluído e documentado.
- Documentado o fluxo “Imagem IA”: `/admin/imagens` + `/api/admin/imagens/{id}/queue` e `/regenerate` usam `ProductImageRequestedEvent`, `ProductImageJobService` e `ProductImageJobRepository`. O README agora descreve `EnqueueResponse`/`JobView`, simplificando o monitoramento e feedback da UI antes de remover o item do README_DEV.
- Registrado o bloco “Clientes (Admin)” descrevendo os endpoints `/api/admin/clientes/{id}/resumo`, `/api/admin/clientes/{id}` (GET/PATCH), ativar/desativar (`/ativar`, `/desativar`), `/pedidos` e `/enderecos` (GET/POST/PUT/DELETE) para resumir contatos, pedidos e endereço; também anotei as próximas entregas de reset de senha/OTP e encerramento de sessões para alinhar o roadmap.
- Documentado o fluxo cliente self-service: `ClienteSelfApiController`/`AccountController` expõem troca de senha, OTP e encerramento de sessões (`/api/cliente/me`, `/api/auth/otp/*`, `/api/auth/resetar-senha`, `/api/auth/password/reset-otp`, logout). O README agora relata quais endpoints ativam esses recursos, e o README_DEV já removeu o passo, mantendo o histórico na seção de configurações.
- Registrada a automação do cadastro por e-mail: `POST /api/auth/register` aceita apenas e-mail/senha, gera nome padrão e CPF temporário quando o usuário não fornece, e mantém as validações de e-mail único/senha forte. Essa mudança apoia o pedido de “cadastrar com email automático”.
- Criado `UserAccountServiceTest` para garantir que o cadastro só com e-mail/senha gera nome/cpf automáticos e persiste com as roles corretas; o arquivo vive no histórico de configurações para futuras referências de QA.
- Registro completo: a subseção “Próximos passos (cliente self-service)” foi reduzida ao plano de UI e testes (sem itens pendentes de backend), porque os endpoints de troca de senha/OTP/encerramento de sessão foram documentados no README e a abordagem de logout foi delineada. Este comentário garante que o checklist pequeno está vazio e que os planos maiores ainda são os próximos focos.
- “Próximos passos sugeridos” no README_DEV foi esvaziado: todos os itens de produtos, testes, Swagger e imagem IA foram movidos para `README.md`/`README_CONFIG.md` e removidos daquele checklist, deixando apenas os blocos maiores e o plano dos 25 passos para futuras iterações.
